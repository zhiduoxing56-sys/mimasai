# 参与方数据流与信任假设

本说明给出待批准的角色边界。已核对的候选 SecGNN 采用三个半诚实且不串谋的服务器，其中两台保存 2-out-of-2 份额，第三台辅助；该来源不证明作品的组合流程满足同一安全结论。[原论文 IV-A 与 IV-B](https://arxiv.org/html/2202.07835)。

| 角色 | 持有的数据 | 可观察的信息 | 禁止或待核对的能力 |
| --- | --- | --- | --- |
| 数据拥有者 | 原始图、特征、标签、拆分随机数 | 上传尺寸、身份、最终授权结果 | 是否也是查询者待原文；不自动获得模型 |
| 主服务器 S0 | 图、模型、中间状态的一份共享；推理存 pk0 密文、sk1 | 本地份额、掩蔽开值、消息长度、时间和停止标志 | 不得获得另一份额或完整模型；不得接收未掩蔽的 pk1 图密文 |
| 主服务器 S1 | 另一份共享；推理存 pk1 密文、sk0 | 同 S0 | S0 与 S1 串谋可恢复全部共享秘密，必须禁止 |
| 训练辅助方 A | 随机三元组及协议需要的相关随机材料 | 离线维度与任务计数；若访问协议在线需消息 | 候选论文要求三方不串谋，不能仅禁止两主方串谋 |
| 推理预处理方 D | 掩码、比较及选择生成种子；原论文还持完整模型并生成两套密钥 | 模型配置、层尺寸、一次性材料计数 | 本作品禁止其恢复完整模型；不得获得查询掩蔽开值；是否保留私钥须规定 |
| 查询者 Q | 查询标识、可选输入及最终结果 | 目标节点概率 | 查询权限、输出节点数量和频率控制待产品规格 |

预期流向为所有者拆分上传到 S0/S1；辅助方分发互不重复的相关材料；主服务器共同训练；主服务器保存共享参数并完成受保护的发布转换；查询触发推理并向 Q 发最终份额。当前本机独立进程通信与交叉密钥测试分发见阶段二/三更新；没有跨机器认证分发服务。

建议公开配置为张量形状、协议版本、环位宽、尺度、图版本和模型摘要；节点数、D、训练标注掩码、全局编号映射、查询节点、执行层数、收敛标志是否公开须分别决策。零权重填充隐藏真实度的能力取决于统一长度和访问协议，不能因数学结果不变便声称访问模式安全。

一个实体兼任 A 与 D 不一定需要完整模型，但会合并两阶段的视图。若 D 知掩码又能观察开值便可解掩码；若 A 知三元组又与一个在线计算方串谋可能破坏保密性。必须提供覆盖全生命周期的模拟论证，明确腐化是静态还是可跨阶段累积、是否允许服务器与所有者/查询者串谋、是否擦除旧种子。本轮不批准角色合并或将模型恢复给可信经销商。

HyGNN II-B 明确模型拥有者完全可信、用户诚实、两云半诚实不串谋，且云不与用户或模型拥有者串谋。VI 的公开泄露包含 BFV 参数、n、k、节点数、请求节点数及各层维度。这些是参考论文提供的假设，不自动成为作品批准的角色合并方案。

阶段零纯 BFV 本地测试仅证明参数、算术和提取打包路径；后续选择密钥及交叉转换状态见追加章节。仍无恶意安全、消息认证、访问隐藏或组合安全证明。噪声预算只在测试端持私钥检查，不作为在线对外接口。

## 阶段一参考边界

S0/S1角色写入各参数份额文件；独立测试进程可见两份、明文权重、梯度和全图输出，用于数值核对，不代表实际参与方视图，也不增加任何允许串谋假设。共享刷新代数测试不构成多方刷新协议。正式发布仍禁止恢复完整参数给模型拥有者，辅助方与推理预处理方能否合并仍待协议安全分析。

## 阶段二第一轮采用的假设

本轮明确采用两计算方半诚实、至多一方被动腐化、S0与S1不串谋；可信离线预处理方T按协议生成正确且独立的一次性材料，T不与任一计算方串谋，不读在线输入或在线掩码打开值。预处理可信性不是服务器生成材料后互相校验所得，亦无三元组牺牲/MAC/主动作弊防护。T同时知道完整随机材料，若观察在线乘法打开消息可恢复输入，所以离线时序与不观察假设是必要条件。

代码将T放在单独进程、在线文件创建前退出；两个在线进程各只读取自身输入/材料，恢复只由验证进程进行。验证端为测试拥有完整夹具和输出，两方资料由它布置；部署时它不应作为额外旁观方收集内部状态。相同机器、相同Unix用户的进程分离与应用文件读取审计不构成操作系统隔离或跨机器身份认证。socketpair没有TLS或消息MAC；当前实验假定连接正确、无窃听/篡改攻击者。公开视图包括操作顺序、形状、位宽/精度、随机会话/批次标识、材料数量、消息长度、迭代/失败状态与时序，不公开未掩码的符号、低位或范围。

独立进程和输出一致性是运行证据；原语依据和组合推导是条件性安全说明，测试不能替代安全证明。阶段二T的可信身份不自动确定后续训练辅助服务器A与T合并，旧组合信任问题仍阻塞。状态账本需可信保存且不可回滚；删除账本不在本轮半诚实模型内。

## 阶段二第二轮新增边界

沿用两方半诚实、可信离线方不与计算服务器串谋且不读取在线输入/打开消息的假设。真实DPF密钥、输入掩码和仿射选择份额在离线生成，每方只加载自己的根种子与材料。新增公开信息为公开k及整批缩位范围是否有效的一个标志；不公开单元素有效位、失败位置、符号或选择位。逻辑通信轨迹与形状由公共规模决定，测试比较了不同符号、不同失败位置的轨迹；Python执行时间不构成物理侧信道恒定时间证明。

布尔基准继承原共享门假设；真实FSS另依赖128位种子、域分离SHAKE扩展的计算安全和DPF组合构造，测试正确不能代替安全证明。本机进程验证不是跨机器认证部署。可信状态不可回滚，整批保留/消费记录不得重置。训练辅助方是否与可信离线方合并仍待确定。

## 阶段三第一轮持钥、数据与新增阻塞

两在线服务器继续半诚实、不串谋；可信离线三元组/daBit/FSS方只见公开计划并在在线输入存在前退出。独立离线密钥设置端在测试中加密已知图传播夹具并生成两组密钥；它不读取模型权重或在线T份额/转换消息。不自动将它与训练辅助方合并。验证端拥有合成图、参考数据和V测试私钥，只在独立测试中恢复和检查噪声；服务器没有恢复函数。

本轮实际持钥：S0持pk0/gk0与sk1，S1持pk1/gk1与sk0，不加载自身计算公钥对应私钥。Python读取审计拒绝另一角色和V目录，C++求值/解密分别按固定模式只打开自身计算材料或对方密钥；同Unix用户与应用审计仍不是OS隔离。在线服务器看到自己的份额/掩码、对方完整掩码密文及自己解密的完整掩码多项式、批次范围标志与公开尺寸/顺序/标识/计时。

全部明文系数均匀掩码保护已经验证；接收方持私钥时的密文与噪声视图隐私仍阻塞。128位SEAL参数检查保障的是参数层面的RLWE强度，不是电路隐私。没有悄悄增加“接收方只看解码明文”的信任假设来隐藏这一缺口。需在可信包、正确密钥设置、非串谋离线、不可回滚账本、无主动作弊的条件之外，解决该模拟/净化问题才能安全部署转换。
