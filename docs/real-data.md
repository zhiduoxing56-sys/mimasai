## 单一入口与公开实验约定

运行 `sh scripts/run_real_data.sh`；可显式传入共享训练轮数，默认读取 `config/phase0.json:data_experiment`。首次需要原站下载或在 `deps/downloads/cora.tgz` 提供锁定文件。直接运行 `python3 verification/real_data.py --archive PATH` 可导入同一内容，不接受未锁定数据悄悄代替。依赖仍按现有锁定清单恢复，没有新增机器学习框架依赖。

数据拥有者在 `src/data.py` 解析完整原始图。默认从最小数值节点编号35开始 FIFO BFS，按数值排序邻居选择16节点，不用标签或测试效果选择节点。保留所有七个类别编号，即使子图某些类缺席。选定节点后的诱导边重新归一化，**不是全图传播后目标节点的等价结果**。引用记录转为无向单位权边，重复/反向记录按既定规则求和；拒绝原始自环，统一补一次单位自环，再做对称归一化。删除在该子图全为零的词列，在该图上是无损的零梯度列删除；记录198个原列编号。每行词特征做 L2 归一化。

固定公开节点 ID 哈希划分：16节点8/4/4，32节点16/8/8，64节点32/16/16。标签不参与划分或节点选择。参数选择不使用测试集；报告独立浮点验证曲线、固定160轮参考预算、验证集最低点与共享训练预算。随机种子只用于公开可复现的初始权重，不用于密码学材料。两层、隐藏宽3、隐藏ReLU、输出无ReLU、公开零偏置、学习率0.5延续配置；类别/特征维度绑定每份模型。

**输入准备假设**：原始图、特征、标签是公开基准；归一化在拥有者侧明文完成。随后在线仅读取各自份额。这不是私人图归一化、私人数据集保密部署或隐藏查询实现。

## 32位/f12 新范围策略

原维度预算 `d*Amax*Bmax < 2^31` 在16节点 P×状态处因 `16*8192*32768=2^32` 拒绝，而不说明真实整数乘积发生了溢出。前向第一层198个特征也会被原预算拒绝。

新增 `range_strategy=row_l1`，默认历史路线仍为 `dimension`。只在原维度界不足时启用以下秘密检查：

1. 按既定有符号缩位范围验证 A、B；公开验证 `d*Amax<2^31`，保证绝对值和自身不会回绕。
2. 秘密取符号、通过单位选择乘法得到 `abs(A)`，不公开符号；在环内求每行绝对值和。
3. 安全比较 `L1(Arow) <= floor((2^31-1)/Bmax)`。只打开全批通过位，失败终止且不写输出，材料作废。
4. 通过后执行原有整个点积乘加，结束后只精确截断一次。

任意乘积及任意前缀和绝对值均不超过 `sum(abs(Aj))*Bmax <= 2^31-1`，故是在乘法**之前**建立原整数范围保障。它没有把回绕后的激活检查当成未溢出证明，也没有改变环或数值顺序。保守 Bmax 仍可能拒绝靠抵消才能安全的实际点积；这属于已说明的适用限制。

本16节点量化 P 最大行 L1=10426、X 最大行 L1=20475、X转置最大行 L1=9775；P及反传 X转置乘状态的限额65535。数值仅是独立验证端测量，服务器仍执行秘密守卫。所有动态状态、权重和更新仍使用现有范围规则。范围检查公开的整批有效位是新增泄露，失败时可知某批越界，但没有位置、值或范数。

分块累加后在同一32位环合并不能自动消除最终总和溢出；逐块截断会改变既定模型语义。更宽环还需要经验证的受保护跨环转换，并会影响 SEAL t、BFV舍入和发布接口，本轮未采取这两条路线。隐私索引训练仍保留原容量限制；真实数据训练使用明确标注的秘密共享稠密 P 矩阵路线，没有静默替代秘密邻居协议的声明。

## 持久材料与连续训练

`verification/real_data.py` 每轮生成全新离线材料与会话。后续轮的权重输入直接取本角色上轮输出尾部份额；独立验证端可以恢复核对，但恢复值不作为在线模型输入。`--resume` 核对源数据、维度、节点顺序和检查点与独立参考，再用新材料继续，不重启旧批次。

消费账本增加连续区间表 `consumption_spans`：每次消费在发消息前以 FULL 同步事务记录 `(batch,kind,start,count)`。整批预留仍持久发生在连接前；中断后不能重启，余量仍烧毁。历史逐条 `consumption` 表和旧账本全部保留，没有清理或回滚。新记录是索引区间，不是降低唯一性要求的缓存。验证检查区间连续、消费量一致及拒绝后重放失败。

## 持续共享发布与同模型推理

`verification/real_chain.py` 从真实训练输出读取各自份额，调用原 f12范围验证/刷新、秘密精确截断5位至f7、范围验证及刷新。只转移本角色发布文件；随机模型ID不依赖参数。独立验证端的恢复仅用于参考对照。

复用 `verification/trained_he_chain.py:run`，通过拥有者构造函数传入本真实 P、节点顺序和词特征；不会使用 `stage3.fixture(16)` 的合成图。SEAL4.1.0真实编码、乘明文、常数项提取、打包、全系数掩码、private_decryption 环乘法和秘密精确BFV舍入不变，tc128始终开启。每层保持线性变换后一次截断和聚合后一次截断。

用同一发布模型、同一输入比较全共享及受保护HE路径，布尔和真实FSS两种激活分别运行。按公开状态界[-8,8)设置f7激活比较位宽11，并执行范围检查；不是用观察到的小数值设通用17位。逐位检查变换原值、聚合原值、截断、激活、输出分数及秘密近似概率。验证端检查全部可解密系数和噪声，不把误差观察交给服务器。

旧 `legacy_ciphertext` 仍仅为正确性诊断且密文视图安全阻塞；新入口不回退。安全论证延续 `he-conversion-security.md` 的条件组合，不计为原论文低交互转换、主动安全或跨机器认证。

工程优化没有降低随机性：离线布尔三元组从一次 `secrets.token_bytes(count)` 的每字节取五个独立随机位，分别用于 a、b和三个本地随机份额，与原逐位 CSPRNG 调用的分布一致。仍是密码学随机源，未用实验初始化种子。

WAL曾作为性能候选做短暂试验，未保留在最终路线：[SQLite 官方 WAL 文档第11节](https://www.sqlite.org/wal.html) 报告3.45.1仍受 WAL-reset 并发缺陷影响，需3.51.3或对应修复版本。当前系统SQLite为3.45.1，最终代码明确使用DELETE journal和FULL同步；由SQLite正常模式转换保存已提交记录，没有手工删除 WAL/SHM、数据库或历史表。历史测量中短暂 WAL 子段不作为最终实现的单独稳定性能数据；干净检出用最终实现重新测量。
