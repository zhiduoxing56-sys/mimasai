## 阶段零历史传播矩阵与多项式编码

以下数值是阶段零历史结果，保存于 results/phase0-reference.json；当前脚本已沿用统一配置改为阶段一带权无输入自环基线。阶段零 verification/reference.py 使用五节点图，包含已有自环、重复边、孤立节点、不同节点度和正负特征。参考去重加自环政策的度为 `[2,4,2,2,1]`；额外验证字面 `A+I` 时度为 `[3,4,2,2,1]`，两种政策确实产生不同归一化矩阵。零权重填充不改变度和加权结果，两种矩阵的五行均通过整数环常数项检查。当前编码尺度 S=128，原始乘积尺度 S²=16384；首行有符号结果 −7360，环值 4294959936，参考 floor 截断为 −58。未实现共享截断。

在 `x^N+1=0` 中 `x^-j=−x^(N−j)`，j=0 留在常数项。编码负指数时必须同时改变系数符号与位置；所有节点索引小于 N，差指数绝对值小于 N，故没有另一组跨 N 碰撞产生常数项。

定点顺序反例在 results/phase0-reference.json（当前 results/reference.json 同样保留该反例）：P=1、X=86、W=192、S=128，`floor(floor(PX/S)W/S)=0`，`floor(P floor(XW/S)/S)=1`。参考实数是相同三因子乘积，但逐步截断不同。结果文件同时保留全图与诱导子图权重反例。早期 S=256 的探索结果保留在 reference-8bit.json，不是第二套配置或当前验收值。

`2^32` 不是 BatchEncoder 可用的明文素数；本路径使用多项式系数打包，qualifiers.using_batching=false 是预期结果。此前 BFVDefault 的探索另存在 he-default-coefficients.json：4096 参数合法但本例密文乘密文噪声为0、解密错误，未计通过；该探索不是论文模数链。

真实路径先把首行归一化权重和特征编码为系数多项式，分别加密，乘法并重线性化。对 `c0+c1*s` 的常数项，直接提取 LWE 样本 `b=c0[0]`、`a=(c1[0],−c1[N−1],…,−c1[1])`，每个 RNS 素数分别处理。提取无需新增评估键且不增加该系数的解密噪声。测试 oracle 对系数秘密向量做点积，再由 Python 大整数 CRT 合成 Q 并按 BFV 舍入解码；已与正确环常数核对。

独立实验打包借鉴 ArcEDB packlwes.cpp 的系数模数归一化与 trace 思路，未直接复制或宣称原库已构建。先在每个 q limb 乘 `N^-1 mod q`，将样本反向嵌入二维 RLWE 密文，再依次 `c←c+σ_g(c)`，Galois 元素为 `N+1,N/2+1,…,3`。trace 消去非常数项；同态自同构需要这些元素对应的 Galois 键。注意 N 在明文环 2^32 中没有逆，不能直接用明文 `1/N`；这里的归一化在系数模数 Q 上进行，trace 后恢复预期常数。原始常数样本和独立权重密文的常数64分别投影，用乘 x 与同态相加打包成 `[−7360 mod t,64]`，其他系数须为0。协议计算段不调用解密或重新加密。

以下为阶段零历史噪声；阶段一新图回归实测见 results/stage1/he-regression.json（随机生成时可相差少量位）：8192 乘明文117、乘密文/重线性化80、投影83、打包83；32768 对应116、77、79、79。全环本地特征份额分别乘明文再同态相加也通过，噪声分别92和91。生成13和15个Galois键。密钥由测试 KeyGenerator 生成；作品的交叉密钥与评估键分发没有实现。噪声只在持私钥的测试 oracle 检查。两标量闭环没有证明任意节点批量、更多层或所有输入范围可用，也不提供打包性能结论。

适用条件是系数形式、size=2、样本同一parms_id和秘密系数向量、每个奇素数q均与N互素、消息与BFV缩放一致，以及最终噪声低于可解码阈值（通常按Q/(2t)估计）。trace结果除原始常数误差外还累积每轮Galois密钥切换误差，后续移位求和和多层乘法继续消耗余量；本轮只量测该样例，未证明输入分布最坏界。

ArcEDB 作者代码 MIT 许可已核对；packlwes.cpp 的 pack_lwe_preprocess 循环看起来一直更新首个 dataB 项，需作者核对，本轮没有修补该外部库。repack.cpp 另含 TFHE→CKKS 路径，不可把它直接作为本项目 BFV 精确打包依据。

## 缩位激活原公式与算法

verification/paper_activation.py 对 n=3、4、5、6、k=n−1，穷举所有输入、n位掩码 rz、布尔掩码 rb，以及布尔常量/比较结果的两种份额拆分。DCF 仅用精确谓词 oracle，没有实现比较密钥。输入掩码比特组合总数为10880，展开两组布尔份额分配为43520组。覆盖零、所有正负边界、模环回绕与缩位越界。results/paper-activation.json 保存每个位宽的失败样例。

令 `zhat=(z+rz) mod 2^n`，`u=zhat mod 2^k`，`y0=u mod 2^(k−1)`，`y1=(−rz mod 2^k) mod 2^(k−1)`，`I=[2^(k−1)−y0−1<y1]`。HyGNN 式1等价于 `DReLU(z mod 2^k) XOR rb = MSB(u) XOR I XOR rp`，其中 `rp=MSB(−rz mod 2^k) XOR 1 XOR rb`。原公式穷举通过；负掩码必须按k位环求MSB。

HyGNN 算法一给双方同一公共 MSB，并在双方均使用 rp,0，重构仅剩 I。即使假设补发了常量，n=3、k=2、z=0、rz=0、rb=0、rp0=0、rp1=1，预期掩蔽DReLU为1，字面算法得到0。若不补发，算法行8本身无法执行行15。比赛算法3.2已发送 rp,i 并使用正确下标，但双方 MSB 仍抵消：同位宽 z=0、rz=2、rb=0，预期1、实际0。

建议修正为仅一方包含公共 MSB，例如 `bhat0=MSB(u) XOR t0 XOR rp0`、`bhat1=t1 XOR rp1`，并正确分发 rp,i；这是本轮建议，不是原文。修正后范围内符号与零点全通过。越界反例 z=2、k=2：原n位DReLU为1，缩位后为0，修正不能弥补缺失的范围保证。

HyGNN IV-C 的 MUX 仿射键关系也穷举通过：针对每个公共 bhat，`α0+α1=bhat XOR rb`，`β0+β1=−(bhat XOR rb)rz mod 2^n`，输出份额 `hi=αi zhat+βi`。这些材料仅依赖随机掩码和位宽，不要求完整模型。确定每层k或形成首层线性缓存却依赖模型、图和输入界。独立通用选择及错误重复公共项的样例另外保存在 reference.json，均未作为安全FSS实现计通过。
