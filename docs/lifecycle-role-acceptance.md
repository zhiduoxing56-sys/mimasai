# 停止、交付异常与角色部署验收（2026-10-06）

审阅基线为 `c9840ed`。本轮完成停止及交付异常路径，使用短夹具验证；操作系统身份创建受管理员权限阻止，未接入页面。没有重新训练、扩大图、关闭范围守卫、历史批量删除或维护虚拟磁盘。原模型、160轮检查点、消费账本、材料标识和既有验收文档保留。

## 本轮实现与状态约束

`src/processes.py` 用 Linux `/proc/*/stat` 的进程组与状态核验是否还有可执行成员，排除不可执行的僵尸；父进程退出和输出管道关闭都不构成停止证明。先向所有组发 TERM，最长等待3秒，再向所有组发 KILL，最后有界核验。扫描失败也会尝试 KILL；不能确认时抛出 `StopUnconfirmed`，不宣称停止完成。范围是本机诚实实现的进程组，未提供恶意进程自行 `setsid` 逃逸的沙箱。

双方执行及单方辅助执行都持有材料锁和工作流锁。单方锁一直持有到监督线程完成后代终止与作废通知。工作进程只继承自身连接，stdin 绑定 `/dev/null`；输入、离线和导出辅助调用也关闭其他描述符并独立监督进程组。

| 状态 | 责任与清理条件 |
|---|---|
| generating / ready | 生成中或等待执行；不可清理 |
| preparing | 应用已独占会话，包含容量准入、输入和报告准备；不可再次启动工作流 |
| running | 后台执行，以及随后保存报告、安装模型或导出最终份额；不可清理 |
| stopping | 中央已拒绝材料，仍待停止确认或角色终止通知；不可清理、不可恢复执行 |
| aborted / completed | 相关进程及通知执行器已停止，有持久停止证明才可清理 |
| cleaned | 先持久保存终止状态及具体清单，再删除允许列表文件；旧材料永久不可用 |

材料锁用于协议/生成；额外工作流锁覆盖准备至交付，清理也获取它。应用内部同线程重入只用于完整工作流内的自动清理，其他线程或进程不能进入。断电/SIGKILL可能留下非终止状态；本轮没有推断恢复或替这些状态自动补证。

中央 SQLite 新增追加事件表，阶段、原因与停止证明独立于应用 JSON 报告保存。输入准备、后台执行、后台报告、两次导出、最终报告和发布安装均在异常收尾内。中央先进入拒绝状态，终止账本由 `src.role_state` 的各角色辅助进程写入，协调器模块不直接打开双方账本。当前这些辅助进程仍是同一 UID；尚未实现受限 OS 身份执行器。

每个角色导出成功会单独记录。只有双方最终份额和最终报告持久保存后才提交 completed；单份交付不能显示完整交付。发布的清理状态也核验原始终止结果；即使报告替换后 fsync 失败留下含 publication 的缓存，aborted 发布仍拒绝新请求和资产准备。保留最终输出份额，但本轮**没有补齐交付接口**，失败会话不可重执行协议。

应用报告写入失败时不能假设缓存已更新，须查询中央持久状态：

```sh
python3 -m src.application status --experiment <实验ID> --request <请求ID>
```

该接口返回会话状态、阶段、交付状态和原因的允许字段，不返回份额、账本、模型或文件路径。现有 CLI 演示仍为 `python3 scripts/demo.py`，复用已有模型；没有增加网页入口，也未重新发布模型。

## 独立短运行证据

完整公共证据在 [lifecycle-role-results.json](lifecycle-role-results.json)，原始新报告在 `results/lifecycle/`。报告分目录保存；同名旧空间测试报告曾被本轮运行覆盖，已从基线聚合证据恢复，其他原验收文档未修改。

- `verification/process_checks.py`：孙进程忽略 TERM 并关闭输出，父进程退出且 communicate 已返回，仍经宽限期 KILL；辅助执行中断时整组停止；检查失败也发 KILL但拒绝完成。
- `verification/storage_checks.py`：内部/宿主不足及宿主未知准入拒绝，生成中和执行中不足，双方/单方抗 TERM 后代停止，秘密描述符未继承，清理前置状态与文件变化拒绝，检查点/ID保留，清理后恢复副本及旧会话重用拒绝。
- `verification/lifecycle_checks.py`：21个短场景，覆盖容量准入、输入准备、首方/次方导出、报告开始/后台保存/最终提交、中断/导出间中断、停止无法确认、发布输入/两方安装/报告保存及替换后失败、离线保存/生成后中断、终止通知无法确认/回执保存失败、交付锁及重复执行、真实导出辅助进程的授权绑定。各新批次均不同；多组真实随机算术三元组的双方视图也独立比较，不把空材料批次当成材料独立性的证明。

应用后台使用保留账本与检查点的合成完成夹具，没有计算 GNN。授权导出测试通过真实角色辅助进程导出合成最终份额。不能把这些测试当成真实分类、新查询成本或密码原语复验。停止无法确认的测试会话按政策保留 stopping，预算仍计入准入；没有擅自改成终止状态清理。

清理实测分别记录前后内部 `f_bavail`、宿主 `f_bavail`、成功 unlink 文件的分配块和当时最后链接的分配块。实际数值见 JSON 的 `storage_checks.cleanup_observation`。内层删除不承诺宿主释放；分配块、可回收上界和可用空间差值不能互相替代，差值也不能自动归因于本次删除。测试注入的 TEST 余量另行标明，真实观测只采用 READABLE 探针结果。

## 管理员部署仍须落实的具体工作

取得本机管理员执行条件后，先建立六个非登录账户并绑定固定 UID；代码/公共配置由管理员持有、各角色只读，不开放通用 sudo Python/命令权限。迁移现有各角色账本到角色独占、可创建 SQLite 日志的目录，保持原数据库内容、材料ID和检查点，禁止重建或清空账本。原 `state/mpc` 共用目录和中央库的只读终止门控需要受限接口/权限设计，不能只 chown 两个文件。

角色执行器应固定本角色、会话、允许动作及授权目标，独占角色账本写入、停止通知和允许列表清理；协调器取得停止/删除块数等公开回执，不能遍历或删除双方私有目录。当前清理源码仍由同 UID 协调器遍历秘密区，尚未改为 OS 受限角色执行器。离线方在独立生成区处理双方相关随机材料，再受控交给对应在线角色；它处理双方随机视图的可信边界继续保留，但不得读在线输入、模型、消息或接收目录。

必须逐项用实际 UID 验证上述允许/拒绝矩阵，检查整个引用链的已有文件、链接、祖先目录、启动描述符和权限，不仅改路径名称。接收端必须只获得当前绑定请求的最终份额能力；一个能读所有历史接收目录的共用账户不满足此要求。管理员可读取/修改材料的边界仍保留。

权限全部通过后才可接入仅监听回环的页面及受限后端接口：固定现有模型、目标和接收端，过滤状态字段，只输出授权最终结果；一次一个请求，幂等请求令牌，刷新/重复提交不重复执行；新请求独立材料，延续容量检查/停止/清理，失败不展示旧结果。**本轮页面未实现、未启动，真实页面查询未执行**，因此没有页面查询验收证据。

已有分类、数值轨迹、160轮结果及原查询成本只引用 [storage-delivery-acceptance.md](storage-delivery-acceptance.md) 与原聚合报告，不是本轮独立运行。角色隔离即使完成也仅是本机部署保障；两方半诚实、可信非串谋离线方、管理员信任及其他原安全限制保持。
